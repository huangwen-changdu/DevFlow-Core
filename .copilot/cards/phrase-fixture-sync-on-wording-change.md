# Phrase Fixture Sync On Wording Change

- Trigger: replacing an exact phrase in AGENTS.md / skills / commands that a validator asserts; trigger:verify or npm test fails with "missing <phrase>"; 文本短语替换, 断言锚点, phrase assertion, validator fixture sync; Markdown 表格列结构变更, 索引加列, table column schema change, fixed-column regex, parseLearningCards
- Lesson: DevFlow validators pin exact source phrases and exact table shapes (validate-skill-triggers scenario evidence, validate-devflow contract asserts, validate-learning-loop's fixed-width index row regex). Replacing asserted wording or adding a table column without syncing the consumer breaks or silently misparses even though the runtime text is correct — the change is only half-done until every fixture and parser that consumed the old shape is updated in the same change. A trailing optional group keeps old rows parseable; a required new column makes the missing field fail loudly.
- Rejected: Rewriting the index row regex to require five columns was rejected because it hard-fails any consumer still producing four-column rows, and the legacy rows predate the column. Leaving the parser untouched was rejected too, because the fifth column would then parse as nothing and an ungraded card would pass silently. The optional trailing group was chosen as the only option that is backward-compatible and still loud.
- Next action: Next time replacing an asserted phrase or changing a Markdown table's column set, first grep the old phrase and the table's file path across scripts/ and docs/; update every fixture anchor (validate-skill-triggers.js, validate-devflow.js, capability-eval-scenarios.json, flow-self-test.md) and every parser (validate-learning-loop.js's row regex, devflow-plan.js's columnIndexes) in the same change, do not wait for the failing check.

- Related: scripts/validate-skill-triggers.js, scripts/validate-devflow.js, scripts/validate-learning-loop.js, scripts/devflow-plan.js, scripts/capability-eval-scenarios.json, skills/devflow-prove/references/flow-self-test.md
- Evidence: 2026-09-23 grill entry build: T1 replaced `creative work with ambiguity or material risk` in AGENTS.md; `trigger:verify` failed `creative-work clarification: AGENTS.md missing ...` until the scenario evidence string was synced. 2026-10-25 learning-card build: before adding the `Evidence Level` column, `validate-learning-loop.js:16` (fixed four-column regex) and `devflow-plan.js:810` (`columnIndexes` by header name) were grepped and read; the regex gained an optional fifth group instead of a rewrite, `npm run learn:verify` printed `Indexed cards: 30`, and `npm run verify:all` exited 0.
