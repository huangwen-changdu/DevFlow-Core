# Local Capability Evaluation Spec

## Goal

为 DevFlow-Core 增加零依赖、可重复的本地能力评测入口。它基于固定场景合同，逐项证明现有流程的路由、证据、负向约束与验证命令仍可执行。

## Context

当前 `npm run scenario:coverage` 从 `skills/devflow-prove/references/flow-self-test.md` 生成场景覆盖地图、薄弱层提示与建议场景；它不逐场景验证能力合同，也不把场景与可执行本地证据命令建立可追溯关联。

现有验证矩阵已经包含 `npm test`、学习闭环、场景覆盖、触发面、宿主适配、安装器、审查、规格、计划和审计等零依赖 Node 命令。本能力复用这些命令，不接入模型 API、外部服务或真实 IDE 宿主。

## Requirements

1. 在版本控制中保存机器可读的能力评测场景清单；每个场景必须具有唯一标识、关联的 `flow-self-test.md` 场景、架构层、预期路由、必需证据、负向约束和一个已注册的 npm 验证命令。
2. 新增零依赖 Node 评测脚本，读取场景清单与 `flow-self-test.md`，验证清单完整性和场景关联性。
3. 评测脚本按唯一 npm 命令执行本地证据，缓存同一命令的执行结果，并将结果映射回关联场景。
4. 控制台输出 Markdown 格式报告，包含每个场景的 `PASS`、`FAIL` 或 `BLOCKED`，预期路由、证据命令、分层覆盖、缺口和复现命令。
5. 清单字段缺失、场景 ID 重复、关联的自测场景不存在、验证命令未注册、必需证据不满足或负向约束不成立时，相关场景必须 `FAIL`，进程以非零状态退出。
6. 验证命令执行失败时，保留命令、退出码和关键输出；所有依赖该命令的场景必须 `FAIL`。
7. 清单不可读取或运行环境异常时，报告整体 `BLOCKED`，不得输出通过结论。
8. 评测脚本自测必须覆盖：全通过、字段缺失、负向约束失败、命令失败和相同命令只执行一次。
9. 在 `package.json` 注册评测与自测入口，并将评测自测和实际评测接入 `npm run verify:all`。
10. 更新 `docs/features/validation-harness.md`，记录新入口、边界、版本历史和关联产物。

## Non-goals

- 不评估模型推理质量、模型成本、token、延迟或真实 IDE 宿主的技能加载。
- 不调用模型 API、网络服务或数据库。
- 不新增第三方依赖、CI 工作流、Hook 或报告存储。
- 不提交运行时生成的报告文件。
- 不替代现有 `scenario:coverage`、触发验证或宿主适配验证；评测只汇总并追溯其本地证据。

## Approach

使用一个显式的 JSON 场景清单作为评测合同，而不是解析自然语言期望。评测脚本复用 `flow-self-test.md` 的现有场景标题作为关联锚点，复用已注册 npm 脚本作为唯一证据来源。

脚本先完成清单、场景关联、命令注册和正负断言检查；再对每个唯一命令执行一次并缓存结果；最后按场景汇总状态。命令输出仅保留报告诊断所需的摘要，避免重复打印完整验证日志。

`scenario:coverage` 继续承担“覆盖地图”职责；新的评测入口承担“能力合同与本地命令证据”的回归职责。

## Impact

- 新增 `scripts/` 下的评测脚本、场景清单及其自测。
- 更新 `package.json` 的 npm 脚本与 `verify:all` 组合。
- 更新 `scripts/validate-devflow.js` 的必需文件、术语与脚本断言，使能力评测成为包内可验证产物。
- 在 `skills/devflow-prove/references/flow-self-test.md` 中补齐或标记可由清单关联的场景信息，仅做支撑评测合同所需的最小调整。
- 更新 `docs/features/validation-harness.md` 的当前能力、非目标、历史、边界与相关产物。

## Acceptance

1. 运行评测命令时，报告展示每个声明场景的状态、预期路由、复现命令、分层覆盖与缺口。
2. 同一验证命令被多个场景引用时，单次评测只执行一次。
3. 有效清单与成功命令使相关场景显示 `PASS`。
4. 缺字段、重复 ID、未知场景、未注册命令、缺失必需证据、负向约束违规和命令失败均产生 `FAIL` 与非零退出。
5. 读取或运行时异常产生 `BLOCKED`，不伪装为 `PASS`。
6. 自测覆盖需求 8 的五种结果，且全量验证矩阵通过。
7. 任何报告或文档都明确：结果仅证明本地能力合同和命令证据，不代表模型质量、成本、性能或真实宿主加载。

## Verification

- `node scripts/capability-eval.js --self-test`：证明全通过、字段缺失、负向约束失败、命令失败与命令去重处理。
- `npm run capability:eval`：生成本地能力合同报告。
- `npm run verify:all`：确认新增入口及现有验证矩阵无回归。
- 审阅报告：确认每个状态均具备场景 ID、路由、命令、证据/缺口与可复制复现命令。

## Code Documentation

评测脚本应以一个文件级注释说明其“本地能力合同评测而非模型基准”的边界；清单校验、命令缓存和状态汇总函数应以简短注释说明其输入、输出与失败语义。场景清单字段使用清晰名称，不需要额外叙述性文档。

## Open Questions

无。命令和文件的最终命名由实施计划确定，但必须保持零依赖、可由 `package.json` 调用，并满足本规格中的行为与验证要求。
