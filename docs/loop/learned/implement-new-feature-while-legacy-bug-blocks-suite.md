# 失败卡: 实现新功能时被旧故意 bug 拖住整份套件

> 摘要: 用途=防止「新目标 + 既有失败断言」并存时被旧 bug 拖红整份测试套件 | 做了什么=记录触发/根因/最小修复/防复发，已召回 2 次 | 复用入口=循环停止条件要求整份测试 exit 0、且套件里可能残留其他循环的失败时 | 更新时间=2026-08-23

- 触发: 循环目标只要求实现新函数（如 divide），但停止条件要求整个测试文件退出码 0；套件里残留上一循环刻意恢复的故意 bug（如 subtract 返回 a + b），导致即使新功能完成测试仍 RED。
- 根因: 停止条件作用域是整个 test.js，而非仅新断言；上一循环"恢复故意 bug 演示 RED"的状态没有在切换循环时回收，新旧循环目标交叉时未先评估既有断言对停止条件的阻塞。
- 修复: 最小动作 = 实现新功能 + 修复阻塞停止条件的既有实现（一行 a + b → a - b），保留全部既有断言不改测试语义；决策理由写入状态文件 R1/R2。
- 防复发: 每循环 R1 先跑停止条件命令拿 RED/GREEN 基线；看到"新目标 + 既有失败断言"并存时，先把"既有断言必须通过才能 exit 0"纳入实现计划，避免把新功能做绿了套件还红着。
