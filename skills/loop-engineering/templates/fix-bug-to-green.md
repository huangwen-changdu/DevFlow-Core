# 循环模板：修 bug 到测试绿

选中本模板后，把「示例」块整体复制进会话并替换字段。

## 字段

```markdown
# 循环定义
目标: 修复「文件/模块」的「症状」，使行为正确
停止条件: `node 测试命令` 退出码 0 且全部断言通过
轮次预算: 8
规模评级: 模型自判（预算为线索；小任务免路线图与子目标链）
产出物: loop/loop-state.md
检查点: 无（可随时打断）
```

## 示例

```markdown
# 循环定义
目标: 修复 demo/calc.js 的 subtract，使减法正确
停止条件: `node demo/test.js` 退出码 0
轮次预算: 8
产出物: loop/loop-state.md
```

## 规则

- 第一轮先复现失败：运行停止条件命令，把失败输出作为证据写进状态文件，再定位根因，再小步修复。
- 每轮结束都运行停止条件命令，把退出码写进状态文件。
- 禁止第一轮就重写整个文件；只改与症状直接相关的最小范围。

## 中大任务区块（可选，模型自判启用）

```markdown
子目标链:
- 子目标1: 复现并定位根因（停止条件: 根因一句话写进状态文件）
- 子目标2: 最小修复（停止条件: `node 测试命令` 退出码 0）
路线图:
- 步骤1: 复现失败 → 验证点: 失败输出入状态文件
- 步骤2: 定位根因 → 验证点: 根因写清
- 步骤3: 最小修复 → 验证点: 测试退出码 0
- 步骤4: 收尾对抗轮 → 验证点: 对抗结论入状态文件
```
