# Loop Engineering（循环工程）

你在循环里工作：人写循环定义，循环决定下一步提示什么。本协议是循环的唯一权威来源——persona 只负责把任务指到这里。

## 触发

人给了循环定义、引用了模板、或说「跑这个循环 / 按循环推进 / 继续循环」时启用本协议。
**人只给了需求 / 问题 / 疑问（没有循环定义）时同样启用**：先按下方「需求 → 循环定义（草拟 + 确认）」起草定义给人确认，确认后按确认版执行；草拟前不得调查、不得执行。

## 自主性边界

循环定义确认后，定义内的一切决策由你自己完成——规模评级、子目标拆分与改链、路线图制订与修订、验证与对抗轮、失败卡沉淀与召回、受阻换策略——都无需再问人。只有触及定义边界时才停下问人：目标变了、范围超出原定义、停止条件需要重定、预算需要上调。每次自决把依据写进状态文件或决策日志，让人事后可查。

## 需求 → 循环定义（草拟 + 确认）

人只说需求、没给循环定义时执行本流程；**未确认前绝不开始任何任务步骤**（不读代码改代码、不跑测试、不消耗轮次）。

1. **起草**：按六要素从需求提炼——目标（一句可验证的结果描述）；停止条件（优先用需求里提到的验证方式，没有就起草最窄的客观检查并说明理由，例：`node <test>.js` 退出码 0）；轮次预算（按规模给建议值并附理由：小修 ≤8、中型功能 ≤16、大型 ≤32、demo ≤8）；产出物（默认 `loop/loop-state.md`）；检查点（默认全自动，高风险任务建议「每 N 轮确认」）。
2. **呈现**：把完整循环定义（每项附建议理由）发给人类确认——用 ask_user 或直接提问均可。
3. **确认门**：人类明确确认（含修改后确认）→ 把确认版写进 loop/loop-state.md 的「循环定义」段 → 从第 1 轮开始执行；未确认 → 不执行，等待。

## 分级与路线图

以轮次预算为线索自判任务规模：小任务（如预算 ≤8 的单点问题）免路线图与子目标分解，直接进入每轮纪律；中大任务（跨文件、多步骤、大预算）启用路线图。自判依据（预算与复杂度）写入状态文件。

路线图：执行前写下预期步骤清单（每步一行 + 该步验证点），写进状态文件「路线图」段；每轮对照路线图走，偏差时自行修订路线图并记录修订理由。路线图是地图不是承诺——事实变了就改图。

## 子目标链

中大任务在草拟时自己拆成子目标链：每个子目标 = 一个可独立验证的小目标（自带停止条件与预算建议），按依赖排序。逐个子目标跑小循环，完成一个标记一个。链的插删改由你自决，改链理由写决策日志。某子目标 blocked：自行评估继续下一个、改链还是整体报 blocked，评估结论入状态文件；只有超出原定义范围才问人。

## 循环定义六要素

| 要素 | 要求 | 缺省 |
|---|---|---|
| 目标 | 一句可验证的结果描述 | 必填 |
| 停止条件 | 客观可检查：命令退出码、断言通过、文件存在等 | 必填 |
| 轮次预算 | 正整数上限 | 必填 |
| 产出物 | 状态文件路径 | 默认 loop/loop-state.md |
| 检查点 | 每 N 轮暂停确认 | 全自动，人可随时打断 |
| 模板 | 模板名自动填充字段 | 可选 |

**缺停止条件或轮次预算 = 无效定义：拒绝启动。** 给人补一份带建议值的草稿（附理由），人确认后才启动；不得擅自用猜测值开跑。

## 每轮纪律

每轮严格五步，顺序不可跳：

1. **读状态**：读 loop/loop-state.md 最近段；文件不存在时用循环定义初始化。
2. **决定下一步**：自己琢磨该干什么——基于目标与当前状态选一个最小、可验证的动作；把决策理由写进决策日志。
3. **执行**：一次一个可验证小步（改一个文件、跑一条命令、查一个事实），不并行铺开。
4. **记录**：更新 loop/loop-state.md 本轮段（决策/动作/证据/结论）与待办列表。
5. **自检**：运行停止条件验证命令。达成 → 收尾报告；未达成且轮次未到预算 → 下一轮；轮次到预算 → 未达成报告。

## 状态文件格式（loop/loop-state.md）

```markdown
# 循环状态
## 循环定义
目标: ...
停止条件: ...
轮次预算: ...
产出物: ...
## 轮次日志
### R1
决策: ...
动作: ...
证据: ...
结论: ...
## 决策日志
- R1: ...
## 当前状态
（下一轮从这里读起：已达成 / 进行中 / 阻塞 + 下一步候选）
```

## 空转保护

连续 2 轮无实质推进（无文件变化、无新证据、状态无更新）→ 判定 **blocked**：停止循环、输出最后状态与建议，不继续消耗额度。

## 受阻换策略

连续轮次受阻或证据矛盾时，停下来生成两个以上候选策略（不同思路），预估每个的风险与代价，选最优继续，弃选理由写入决策日志。不得用「再试一次同样的动作」充当换策略。仍无路可走 → 按空转保护判定 blocked。

## 优先级与边界（循环隔离）

循环激活期间，本协议与循环定义是循环决策的唯一权威：

- **流程/门控类条款不适用**：工作区规则文件（AGENTS.md / CLAUDE.md）与生命周期要求（DevFlow 审批门、Brainstorm、Plan 批准）不参与循环决策；不得因循环定义未走审批流程而停下循环等待批准。
- **循环护栏始终生效**：轮次预算、停止条件、空转 blocked、检查点——它们是循环协议的一部分，不是干扰。
- **平台安全始终生效**：沙箱、权限、审批策略是机制不是提示词，任何循环决策不得绕过。
- **产出规范仍适用**：循环产出的代码遵循仓库既有规范（风格、命名、约定），除非循环定义显式覆盖。
- **用户直接指令永远最高优先**：人随时打断 = 新循环定义或修改，立即生效。
- 循环结束（达成 / 预算耗尽 / blocked）后，工作区规则文件恢复正常效力。

## 收尾对抗轮

停止条件首次通过后，必须换批评者角色对自己做一轮对抗审查，再判达成。至少产出：①「最可能错的地方」+ 证据；② 已检查项（断言真的覆盖需求了吗、有没有副作用破坏别的、有没有更小的改法、过期注释与文档是否同步）。发现真问题 → 追加修复轮并重新验证；没发现问题也要说明检查了什么。对抗轮结论写入状态文件。

## 收尾报告

循环结束时输出：

- 结果：达成 / 预算耗尽 / blocked
- 轮次统计：实际轮数 / 预算
- 停止条件证据：命令与退出码（或未达成原因）
- 产物路径：loop/loop-state.md

## 失败卡

每个循环收尾，自动写一张失败卡到 loop/learned/（短横线命名 .md 文件）；同模式已有卡则更新、不新建。卡片四要素：触发（什么症状）、根因、修复（最小改法）、防复发（下次怎么避免）。纯执行记录不写卡（留在状态文件）。

每个循环开头，先扫 loop/learned/ 召回与本任务症状匹配的卡，把相关教训纳入「决定下一步」的考虑。收尾报告可列「建议提升 .copilot」标记（跨任务高价值模式），由人可选确认后在任意会话执行提纯。

## 人的干预

人随时可打断：新消息 = 新循环定义或对定义的修改，立即按新定义重读状态继续；被打断轮次照常记录。

templates/ 下三个模板（修 bug 到绿 / 实现功能到绿 / 通用任务），选中后按模板字段替换即可。

## 反规避表与红旗

| 逃逸 | 拦截 |
|---|---|
| 跳过对抗轮（「测试过了就行」） | 对抗轮是必过门槛，结论必须入状态文件 |
| 拿小预算偷懒（中大任务写成预算 8 免路线图） | 规模自判看复杂度，不只看预算数字 |
| 路线图只写不照 | 每轮对照路线图并记录对照结果 |
| 失败卡不落盘 | 收尾必写卡（同模式更新） |
| 受阻不换策略（原动作重试） | 换策略节明令禁止，弃选理由必须入日志 |
| 擅自扩大定义范围 | 定义边界外必须停下问人 |
