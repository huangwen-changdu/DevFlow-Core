# Plan → 循环定义翻译模板

把一份已批准的实施计划翻译成循环定义。DevFlow Plan 最顺手；非 DevFlow 格式的计划按字段就近映射即可，映射不到的字段按「缺时怎么办」处理。

## 映射表

| 循环定义要素 | 取自 Plan 的什么 | 缺时怎么办 |
|---|---|---|
| 目标 | Plan 的 Goal / 目标 | 用 Plan 的成功标准改写为一句可验证的结果描述 |
| 停止条件 | Plan 的验收标准 / Verify 命令 | 起草最窄的客观检查（如 `<verify 命令>` 退出码 0）并说明理由 |
| 轮次预算 | Plan 的任务数量与工作量预估 | 按规模给建议值并附理由（小 ≤8 / 中 ≤16 / 大 ≤32） |
| 产出物 | 无（循环产物） | 默认 loop/loop-state.md |
| 检查点 | 无（Plan 的审批门不进入循环） | 默认全自动；高风险任务建议「每 N 轮确认」 |
| 子目标链 | Plan 的任务清单（按依赖排序） | 无任务清单时按 Plan 步骤自拆，理由入决策日志 |
| 收尾对抗轮重点 | Plan 的风险与假设 | 无则按 SKILL.md 默认五查 |

## 用法

1. 把已批准的 Plan 内容按上表填入下方草稿；
2. 把完整循环定义发给人确认（每项附理由）；
3. 确认后写入 loop/loop-state.md 的「循环定义」段，从第 1 轮开始。

## 草稿

```markdown
目标: （一句可验证的结果）
停止条件: （客观可检查 + 理由）
轮次预算: （数字 + 理由）
产出物: loop/loop-state.md
检查点: 全自动 / 每 N 轮确认
子目标链: （可选，中大任务）
- S1: ...（验证: ...）
- S2: ...（验证: ...）
收尾对抗轮重点: （可选，来自 Plan 风险与假设）
```

## 注意

- Plan 的审批门已由人在 DevFlow 侧完成；翻译进循环定义后，循环内不再需要任何 Plan 审批。
- 循环隔离生效：循环激活期间流程/门控条款不适用（见 SKILL.md「优先级与边界」）。
- 执行中发现事实变化时，按循环协议自行改链并记录理由；只有触及定义边界（目标/范围/停止条件/预算）才停下问人。
